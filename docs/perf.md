# 저사양 기기 CPU 측정

`npm run build && npm run perf`로 다시 만들 수 있습니다. 크롬의 CPU 속도 제한(4배, 6배 느리게)으로 보급형 폰을 흉내 낸 값입니다.

- 헤드리스 브라우저에는 GPU가 없어서 화면 주사율 대신 한 프레임(1/60초)씩 직접 돌리며 자바스크립트 시간(게임 로직 + 그리기 준비)을 잽니다. GPU가 픽셀을 칠하는 시간은 빠져 있고, 그건 휴대폰의 `?debug=1`로 봅니다.
- 전투마다 시작, 도로 중간, 보스전에서 300프레임씩 잽니다. 스테이지 10, 20은 그 시점에 예상되는 피난처 강화를 적용했습니다.
- 1% 저점 = 가장 느린 1% 프레임의 시간(99번째 백분위). 예산은 한 프레임 16.6ms, 로직 4ms, 드로우 콜 20회, 메모리 250MB.
- 측정용 조종은 게이트만 고르고 장애물은 피하지 않아서, 스테이지 20은 도로 중간 전에 무리가 전멸해 시작 구간만 잽니다(프레임 수가 적어 1% 저점이 가장 느린 3프레임으로 정해집니다).
- CI(`--quick`)는 4배 조건에서 평균 프레임 CPU 8ms, 로직 4ms, 드로우 콜 20회를 넘으면 실패합니다.
