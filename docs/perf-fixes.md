# 8단계에서 고친 비싼 함수

스트레스 스테이지(병력 5,000)를 CPU 4배 느린 조건에서 600프레임 돌리며 CPU 프로파일을 떠서, 시간을 많이 쓰는 함수부터 고쳤습니다. 프로파일은 실행마다 ±20% 정도 흔들려서, 고치기 전 빌드와 고친 뒤 빌드를 번갈아 3번씩 돌리고 각 함수의 가장 작은 값을 비교했습니다(`npm run perf -- --profile`이 함수별 표를 `artifacts/profile.txt`에 씁니다).

| 함수 | 원인 | 고친 방법 | 전 | 후 |
| --- | --- | --- | --- | --- |
| 피난처 장면 진입 (`CanvasTexture` 생성) | Phaser `textures.addCanvas`가 만든 캔버스의 픽셀을 GPU에서 다시 읽어 옴 | `art/canvasTexture.ts`로 읽기 없이 등록 (7단계) | 3,795ms | 123ms |
| `DisplayList.depthSort` | 무리 스프라이트가 매 프레임 `setDepth`를 불러 장면 전체를 다시 정렬. 효과 파티클이 일반/가산 블렌드를 섞어 정렬 순서가 자주 바뀜 | 깊이는 인원 수가 바뀔 때만 다시 계산. 효과 풀을 일반 125개, 가산 55개로 나눠 각자 고정 깊이 | 29.2ms (정렬 97회) | 10.7ms (정렬 27회) |
| `GateView.update` | 게이트 숫자 옆 아이콘 위치를 잡으려고 매 프레임 `BitmapText` 너비를 다시 잼 | 글자가 바뀔 때 한 번 재서 저장 | 34.5ms | 13.6ms |
| `Effects.update` | 움직이지 않는 파티클에도 매 프레임 위치·크기·투명도를 다시 씀 (쓸 때마다 변환 행렬이 더러워짐) | 값이 바뀌는 것만 씀 | 43.8ms | 36.4ms |
| `BitmapText.getTextBounds` 호출 수 | 위 게이트 너비 재기 | 위와 같음 | 5,457회 | 4,564회 |
| 자바스크립트 전체 (600프레임) | | | 1,415ms (프레임당 2.36ms) | 1,275ms (프레임당 2.12ms) |

남은 시간의 대부분은 Phaser가 스프라이트를 GPU 버퍼에 담는 부분(`batchSprite`, `bufferSubData`)이고, 이건 그리는 스프라이트 수(최대 200개, 저사양 120개)에 비례합니다.

# 11단계: 3D 전투에서 고친 것

| 문제 | 원인 | 고친 방법 |
| --- | --- | --- |
| 좀비나 바리케이드가 처음 보일 때 한 번 크게 멈칫 | 셰이더는 `compile()`로 미리 만들어도 처음 그릴 때 연결(link)과 검사를 해서 그 프레임이 GPU를 기다림 | `World3D.warmUp()`이 숨은 것까지 모두 1픽셀 화면에 한 번 그려 둠. 셰이더 오류 검사(`checkShaderErrors`)는 `?debug=1`에서만 |
| 측정에서 가끔 한 프레임이 수십 초 | 헤드리스 브라우저의 소프트웨어 GPU가 밀린 그리기를 다음에 GPU를 기다리는 호출(위 셰이더 검사)에서 한꺼번에 처리 | `npm run perf`가 프레임마다 1픽셀을 읽어 앞 프레임 그리기가 끝난 뒤에 잼(`finish()`는 크롬에서 기다리지 않음). 측정 시간을 줄이려고 캔버스는 CSS 픽셀 1배 |
| 측정에서 성능 오버레이가 몇 프레임마다 다시 그려짐 | 손으로 돌리는 프레임이 실제보다 훨씬 느려 0.25초 갱신이 자주 옴 | 측정 중에는 오버레이 갱신을 끔(`monitor.snapshotIntervalMs`) |

스트레스 스테이지 4배 느린 CPU: 프레임당 자바스크립트 6.2ms. Three.js 그리기가 1.9ms(그중 Phaser와 화면을 나눠 쓰느라 상태를 되돌리는 데 0.5ms), 3D 세계 갱신 1.0ms, 나머지가 전투 규칙과 Phaser HUD입니다. 유닛 수와 상관없이 모델마다 드로우 콜 1회라 드로우 콜은 11~15회입니다.

# 12단계: 3D 로비와 피난처

| 문제 | 원인 | 고친 방법 |
| --- | --- | --- |
| 효과 버퍼를 GPU에 올리는 데 프레임당 약 0.6ms(4배 느린 CPU, 스테이지 20) | 위치·방향·크기·색·프레임을 버퍼 5개로 따로 올리고, 프레임마다 그 목록을 배열로 새로 만듦 | 한 버퍼에 섞어 담고(`InstancedInterleavedBuffer`, 칸 13개) 한 번에 올림 |
| 로비·피난처 3D 세계가 처음 보일 때 멈칫 | 셰이더를 처음 그릴 때 연결 | 타이틀에서 전투·피난처 세계를 함께 받아 `warmUp()`(`registry.ts`의 `load3D`) |
| 피난처 건물 15모양(5종 × 3단계) 교체 | 업그레이드마다 모델을 새로 만들면 GPU 자원이 늘어남 | 처음에 모두 만들어 두고 메시의 지오메트리만 바꿈. 렌더러는 전투와 같이 씀 |

피난처는 드로우 콜 13회(3D 11회 + 글자·HUD 2회), 로비는 11~15회입니다.
